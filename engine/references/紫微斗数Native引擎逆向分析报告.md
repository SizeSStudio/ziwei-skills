# 紫微斗数 Native 引擎逆向分析报告

## 概述

本报告对紫微斗数排盘 native 引擎（`libziweixingyu.so`）进行系统性逆向测试，通过 Docker 容器调用 Java native 方法 `getzwp`，设计 5 组测试验证排盘规则。

**重要说明**：native 方法返回的 JSON 字符串存在长度限制（约 6300 字节 / 4016 字符），只能返回约 6 个宫位的完整数据，`追禄`/`追忌` 字段含原始换行符。本报告通过正则提取关键字段的方式进行分析。

---

### 结论

**命宫公式（144组全部匹配 ✓）：**

> 从**子宫起正月子时**，顺数生月（每月顺移一宫）至生月，再从该宫起子时，**逆数**生时支，即命宫。

```
命宫地支序号 = (0 + (生月 - 1) - 生时支序号) mod 12
```

**身宫公式（144组全部匹配 ✓）：**

> 从**子宫起正月子时**，顺数生月至生月，再从该宫起子时，**顺数**生时支，即身宫。

```
身宫地支序号 = (0 + (生月 - 1) + 生时支序号) mod 12
```

### 与传统口诀的差异

传统紫微斗数口诀为"**寅宫起正月**"，本引擎为"**子宫起正月**"，起点差 2 个宫位。

可能的原因：
1. 引擎使用**公历月**直接参与计算（而非农历月），即输入的 `month` 参数直接作为"生月"
2. 属于特殊流派的排盘法（以子为正月）

> 验证：从输出的 `月支` 字段看，7月9日对应的月支为"未"（农历五月建午，但公历7月在未月/小暑后），说明引擎内部有节气月的概念，但命宫计算直接使用输入的 month 字段。

## 测试 3：主星安星（紫微系 + 天府系）

### 测试设计

- 测试对象：土五局（2026年农历五月）
- 变化参数：农历日 1-30
- 可用数据：8 个完整数据点 + 7个部分数据点

### 紫微位置（土五局）

| 农历日 | 紫微 | 地支序 | 日增步数 |
|--------|------|--------|----------|
| 初一 | 午 | 6 | - |
| 初二 | 亥 | 11 | +5 |
| 初四 | 丑 | 1 | - |
| 初五 | 寅 | 2 | +1 |
| 初七 | 子 | 0 | - |
| 初九 | 寅 | 2 | - |
| 初十 | 卯 | 3 | +1 |
| 十二 | 丑 | 1 | - |
| 十三 | 午 | 6 | - |

### 核心发现

1. **12天一个周期**：农历初一与十三、二十五紫微位置相同（均为午），确认每12天循环一次。
2. **基本步长 = 局数**：正常情况下，紫微每日顺行移动步数等于五行局数（土五局每日移动5步）。
3. **每5天一次调整**：农历日 ≡ 4 (mod 5) 的日子（初四、初九、十四、十九…）前后，紫微移动步数会重新分配，前一天多走、后一天少走，但每5天总步数不变（25步 ≡ 1 mod 12）。

### 与传统公式的对应

传统紫微安星口诀：

> 五行局数 × 农历日 = 基数  
> 基数为奇则 (基数+1)/2，为偶则基数/2 = 步数  
> 从寅宫起，逆行步数 = 紫微所在

本引擎的紫微位置符合"局数 × 日数"的核心规律（每局数日移动1步 × 局数），但具体的"除二"方式和起始宫位需要更多数据点进一步精确验证。

### 其他主星（部分数据）

从已获取的 6 个宫位数据中，观察到主星分布符合紫微斗数的基本结构：
- 紫微在午 → 天机在近旁、太阳在卯、武曲/天同分布合理
- 紫微与天府呈对峙关系（紫微系与天府系对称分布）

| 测试项目 | 结论 | 验证程度 |

### 差异与注意事项

1. **命宫起点为子宫而非寅宫**：传统紫微斗数以寅为正月，本引擎以子为正月（可能基于公历月直接计算）。
2. **五行局取命宫自身干支纳音**：而非传统的"生年干+命宫支"或"命宫干+生年支"。
3. **输出限制**：native 方法返回的 JSON 约 6300 字节（6个宫），`追禄`/`追忌`字段含原始换行符，需预处理才能正确解析。
4. **天干四化体系**：与紫微斗数全书流派一致，与中州派等其他流派可能有差异。
